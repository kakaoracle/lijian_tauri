# moyu_tauri

`moyu_tauri` 是一个基于 Tauri 2 的 Windows 桌面应用，用来替代原 Electron 版 `moyu`，目标是减小体积、保留原有学习流程，并维持透明窗口相关能力。

## 1. 项目目标

- 用 Tauri 重建原应用，降低桌面包体积。
- 保留四类核心业务：
  - 玻璃网页
  - 速算训练
  - PDF 阅读
  - 言语词语积累
- 启动页、速算、PDF、词语积累等标准业务窗口优先使用 Windows 系统原生标题栏与系统缩放行为；仅在确有必要的特殊窗口中才保留自定义窗口结构。
- 面向 Windows 运行，依赖系统已安装 WebView2 Runtime。

## 2. 当前功能总览

### 2.1 主窗口 Launcher

- 作为入口页，负责打开各个业务模块。
- 可打开玻璃网页窗口。
- 可打开速算训练窗口。
- 可选择 PDF 并打开 PDF 阅读器。
- 使用统一的设置面板，控制主题、透明、模块开关等配置。
- 首页默认窗口尺寸为 `820 × 620`，最小尺寸为 `820 × 560`，刚好容纳四个等权模块及必要状态区。升级后会执行一次紧凑尺寸迁移，清除旧版本可能保存的异常超高首页尺寸；迁移完成后仍继续记忆用户后续手动调整的尺寸。
- 首页窗口会记忆用户最后一次手动调整后的尺寸，下次启动时按上次尺寸恢复。
- 首页遵循“备考功能完整、办公场景低存在感”两项原则，不显示“备考工作台”“公务员考试”等用途暴露文案，不使用鲜艳强调色。
- 首页优先采用 iOS 设计原则：清晰层级、成组控件、统一几何、克制材质、有效留白、紧凑符号与轻量动效；在办公场景下使用低饱和石墨色而不是醒目的系统蓝。
- 首页采用四模块等权的 `2 × 2` 布局：玻璃网页、速算、PDF、词语积累。
- 网址选择属于玻璃网页模块内部，不拆成独立“网页入口”；词语积累与另外三个模块并列，不作为附属区域。
- 首页使用固定低调标题区、四模块自适应内容区和底部状态区，不使用页面滚动条承载正常内容。

### 2.2 玻璃网页

- 打开一个远程网页并尽可能透明化。
- 当前玻璃网页窗口优先采用 Windows 系统原生标题栏；正文网页区域仍由独立内容 WebView 加载实际目标网站。
- 当前有针对粉笔类页面的个性化透明处理。
- 支持统一透明脚本、同窗口导航控制、局部站点适配。

### 2.3 速算训练

- 支持题型下拉选择和题量选择。
- 支持训练过程计时、逐题作答、最终评级、结果回顾。
- 支持历史记录和薄弱项统计。
- 可根据慢题和错题特征做“薄弱项强化出题”。

当前题型如下：

- `五位数除三位数`
- `三位数加减`
- `两位数乘一位数`
- `三位数除一位数`
- `11-19 乘一位数`
- `16 乘一位数`
- `17 乘一位数`
- `18 乘一位数`
- `19 乘一位数`
- `2*2估算`

其中：

- `2*2估算` 为本次新增题型。
- `2*2估算` 的判定误差为 `5%`。
- `2*2估算` 的评级标准按每 10 题计算：
  - `Excellent`: `32s`
  - `Good`: `40s`
  - `Pass`: `48s`
- 超过 10 题时，评级阈值按题量等比放大。

### 2.4 PDF 阅读器

- 支持选择并打开 PDF。
- PDF 页面内不再保留翻页、页码输入或缩放工具栏，避免与 Windows 原生 `文件 / 设置 / 帮助` 菜单重叠；阅读区从原生菜单下方直接铺开。
- 支持连续滚动、鼠标滚轮、按住页面拖动，以及 `PageUp` / `PageDown` 逐页导航；`Ctrl+0` 可恢复 `100%` 缩放。
- 阅读器打开时，可通过系统原生菜单「设置 → 放大 (Zoom In) / 缩小 (Zoom Out)」调整页面内容，每次变化 `15%`。缩放请求在页面渲染繁忙时会排队，连续点击会累计目标，空闲后只进行一次布局与可见页重渲染，避免旧实现逐帧重画导致十几秒内看似不生效。
- PDF 字体不做替换，继续使用文件内嵌字体和 PDF.js 原生文字布局。Canvas 渲染倍率会根据当前缩放、屏幕 DPI、页面尺寸和单页像素预算自适应；放大时不再固定进行过量超采样后缩小显示。
- 当前页按阅读区顶部附近的页面判定，避免窗口较高时因中心点跨过多页而让“下一页”一次跳两页。
- 支持透明模式、黑白模式、隐藏图片。
- 黑白模式使用保留抗锯齿灰阶的柔和亮度曲线；透明黑白模式用连续透明度表达文字边缘，不再把中间灰阶压成接近纯黑，从而降低放大后的过度锐化感。图片显示/隐藏规则不变。
- PDF 默认开启“裁切左右页边距”：每页渲染后独立识别两侧空白，仅裁水平方向并保留约 `12px` 安全边；若识别结果会让正文宽度小于原页 `60%`，则放弃裁切。特殊排版可在 `设置 → 偏好 → PDF 阅读` 中关闭该选项。
- 全局主题新增“夜间”：所有业务窗口使用低亮度中性色；PDF 会优先切换为黑底白字。PDF 设置中同时保留独立“夜间模式”开关，可在其他全局主题下单独启用，并持久化到 `settings.json`。
- 夜间模式不改变“隐藏图片”的业务开关与图片区域识别逻辑；图片是否显示仍完全由原设置决定。
- 支持保存阅读进度和视觉模式。
- 当前页码会在阅读过程中自动保存，并在下次打开同一 PDF 时恢复到上次阅读页。
- PDF 页面采用“首屏优先、其余页面按需加载”的增量加载策略，不再在打开阶段一次性同步抓取整本 PDF 的全部页面对象，避免大文件导致窗口按钮、翻页、拖动和滚轮交互假死。
- PDF 视觉模式或夜间设置在页面渲染过程中发生变化时，不会提前释放正在使用 canvas 的旧渲染任务；旧任务结束后再调度最新视觉版本，避免同一 canvas 并发渲染导致阅读器异常。
- PDF 阅读区必须固定占满窗口内容区并由自身承担滚动；不能让阅读区随全部页面总高度增长，否则 `clientHeight` 会等于 `scrollHeight`，导致滚轮、拖动和翻页全部失效，并误判整本 PDF 都在可视区。
- PDF 打开、按需页加载、单页渲染耗时、翻页、节流后的滚动、拖动起止及异常均写入应用数据目录下的 `debug.log`；禁止逐条记录鼠标移动事件。日志达到 2 MiB 后自动截断重建，避免高频交互拖慢 UI 或长期占用磁盘。

### 2.5 言语词语积累

- 面向公务员考试“言语理解与表达”中的选词填空与词语辨析积累。
- 首页可选择本地 TXT 文件，当前支持 UTF-8、UTF-8 BOM、UTF-16 LE、UTF-16 BE 编码，单个文件最大 8 MB。
- “开始提取”和“查看已有积累”为两个独立操作：提取完成后停留在首页，由用户决定何时进入二级页面，不自动跳转。
- 提取在独立 Web Worker 中离线执行，首页持续显示处理阶段和百分比，并提供“取消”按钮；提取期间暂时禁用查看入口，确保取消操作始终留在当前页面；取消后立即终止后台任务且不保存未完成结果。
- 常考词识别、考试型搭配和例句整理均采用按句单遍扫描，只保留与公考选词填空、词语辨析相关的预设词表与预设搭配，不再把开放式高频碎片词组直接收进词库。
- 同一路径的 TXT 再次提取时覆盖旧结果，避免重复导入导致权重虚高；不同 TXT 作为独立来源累计并重算权重。
- 首页的入口文案为“打开词库”，避免使用冗长的“查看已有积累”。独立二级页面以表格展示词语、词类、权重、出现次数、来源数、常见搭配和单条例句；每页最多渲染 100 项，避免大量积累导致窗口长时间空白或卡死。
- 二级页先绘制窗口骨架，再在 Worker 中聚合历史来源；聚合未完成时页面仍可立即关闭，不阻塞窗口交互。
- 二级页对来源读取设置 10 秒超时、Worker 聚合设置 15 秒超时；超时会终止并释放 Worker，显示错误而不是无限空白。若 Worker 异常，使用受边界约束的快速聚合兜底，确保已有词库仍可查看。
- `vocabulary_open` 必须保持为异步 Tauri 命令；窗口创建不能放在同步命令中占用 Windows 主事件线程，否则会造成整个程序 `AppHangB1`，连关闭按钮也无法响应。
- 打开词库、创建窗口、读取来源、Worker 聚合和首屏渲染均写入应用数据目录下的 `debug.log`，排障时按 `[vocabulary]` 与 `[vocabulary-ui]` 检索完整阶段链路。
- 打开词语积累二级页面时隐藏首页；关闭窗口右上角叉号后恢复首页，不再额外保留页面内“返回”按钮。
- 词语积累二级页面也会记忆用户最后一次手动调整后的窗口尺寸，下次打开时按上次尺寸恢复。
- 支持搜索、词类筛选、权重/频次/来源/词语排序、移除单个来源、逐词删除以及黑名单恢复。

## 3. 业务逻辑说明

### 3.1 窗口模型

全应用默认优先使用系统标准窗口标题栏；只有特殊窗口能力不足时才补充自定义窗口结构。

- `Launcher`、`速算训练`、`PDF 阅读`、`言语词语积累`：普通 `WebviewWindow`，入口都来自 `dist/index.html` 的不同 hash 路由；Windows 下保留系统原生标题栏与缩放行为。打开业务二级窗口时隐藏 Launcher，二级窗口关闭后恢复 Launcher。
- `玻璃网页`：使用原生 `Window` 承载单个远程内容子 WebView；Windows 下保留系统原生标题栏与缩放行为，不再额外叠加本地标题栏壳层。
- 这样做的目的，是把标准窗口的拖拽、悬停和缩放体验交回系统处理，同时继续避免把项目内控制逻辑直接注入第三方网页 UI 结构。

### 3.2 透明实现策略

不同模块各自实现透明逻辑，不共享一套渲染方案。

- 玻璃网页：
  - 重建远程内容窗口和子 WebView
  - 注入透明 CSS 和脚本
- 速算训练：
  - 保持本地页面，通过 class/style 切换透明样式
- PDF 阅读：
  - 用 PDF.js 先渲染到 canvas
  - 再对像素做透明化或黑白化处理

设置与联系统一恢复到 Windows 原生菜单栏中的 `文件 / 设置 / 帮助`，不再依赖页面内按钮；PDF 也只保留这套原生菜单，不再叠加页面内翻页/页码/缩放栏。二级页返回统一使用系统右上角叉号。
- 原生菜单动作由 Rust 直接派发到目标 WebView，不依赖被 ACL 拒绝的前端事件监听；这样 `设置 → 偏好`、`放大 (Zoom In)`、`缩小 (Zoom Out)` 都能稳定到达业务页面。

### 3.3 设置与持久化

设置保存在 Tauri 应用数据目录中。

主要数据文件：

- `settings.json`
  - 全局透明
  - 主题，包括雾灰、纸白、墨蓝、松绿和夜间
  - 模块设置
  - PDF 夜间模式
  - 窗口尺寸
  - 首页紧凑尺寸一次性迁移状态
- `pdf-reader-progress.json`
  - PDF 页码进度
  - 视觉模式
- `vocabulary-sources.json`
  - TXT 来源路径、文件名、提取时间、文本规模
  - 每个来源独立的词语频次、词类、搭配和例句
  - 逐词黑名单；黑名单词在后续所有提取保存时都会被自动过滤
  - 最多保留 100 个来源，同一路径更新时覆盖旧来源
- 心算历史文件
  - 由 Rust 侧 `mental_math_history_*` 相关命令维护

### 3.4 速算训练评分逻辑

速算训练评分相关逻辑在：

- `src/mental-math-engine.js`
- `dist/mental-math-engine.js`

规则说明：

- 每个可评级模式定义一组“每 10 题”的阈值。
- 实际训练题量为 `10 / 20 / 30 / 50` 时，系统按 `题量 / 10` 等比放大阈值。
- 训练结束后，按总用时与放大后的阈值比较，输出：
  - `Excellent`
  - `Good`
  - `Pass`
  - `Fail`

本次修复内容：

- 修复了“超过 10 题后评分阈值重复放大”的问题。
- 现在 20、30、50 题都会按一次等比扩展，不会失效。

### 3.5 言语词语提取规则与维护方法

提取规则以“对公考选词填空和词语辨析是否有复习价值”为优先级，不追求通用自然语言分词的全覆盖。

当前收集范围：

- `实词·动词`：推动、促进、完善、遏制、彰显、契合、化解、统筹、夯实等，重点关注动作对象和搭配差异。
- `实词·形容词`：深刻、显著、严峻、迫切、脆弱、稳妥等，重点关注修饰对象和语义轻重。
- `实词·名词`：根基、动力、机制、效能、瓶颈、契机、边界等，重点积累政策语境搭配。
- `虚词·关联词`：不仅/而且、虽然/但是、因为/所以、只有/才、无论/都等，服务于逻辑关系辨析。
- `虚词·副介词`：尤其、愈发、进而、从而、基于、鉴于、围绕等，服务于语气、递进和因果关系辨析。
- `成语`：维护公考常见、易混、语境限制明显的成语词表。
- `考试型搭配`：只维护与公考高频词相匹配的预设搭配，例如“推进改革”“完善机制”“提升效能”等，用于帮助复习固定语境。

保留与排除规则：

- 考试词表中的词语出现 1 次即可保留，避免漏掉低频但有辨析价值的词。
- 不再根据全文高频自动扩展开放式 2 至 4 字候选，避免把“改革”“发展”“习近”“化改”这类缺乏刷题价值的政策语料碎片收进词库。
- 仍排除单字、纯数字中文写法、连续重复字、网址、常见人称代词、泛化新闻套话和低信息停用词。

搭配、例句和权重：

- 搭配只从预设考试型搭配表中命中并统计，单一来源保留频次最高的 3 个，跨来源汇总后保留前 5 个。
- 每个词在单一来源中只保留 1 个去重例句；跨来源汇总后界面只展示 1 条例句，并标明来源 TXT 文件名。
- 若词表中已维护近义辨析说明，则随词条一并保存并参与展示/搜索。
- 在词库页点击“删除”会把该词从当前全部来源中移除，并加入持久化黑名单；后续重新导入 TXT 时仍会继续跳过。
- 黑名单词可在词库页“已屏蔽词”区域手动恢复；恢复后只影响后续提取，已经从旧来源中移除的词不会自动回填。
- `总出现次数`为该词在所有来源中的次数之和，`来源数`为包含该词的独立 TXT 数量。
- `权重 = 总出现次数 + 2 × (来源数 - 1)`，跨不同材料反复出现的词获得额外加权。
- 同一路径重新提取采用覆盖而不是累加；移除来源后权重根据剩余来源实时重算。
- 提取性能规则：常考词计数、高频候选统计以及入选词的搭配/例句分别按语句单遍扫描，不允许恢复为“每个词重新扫描全部句子”的实现。
- 进度阶段依次覆盖文本读取、常考词识别、高频词组统计、搭配与例句整理和完成；耗时计算必须在 Worker 中执行，并允许首页直接取消。

规则维护位置：

- 规则源码：`src/vocabulary-engine.js`。
- 打包运行时副本：`dist/vocabulary-engine.js`。
- 自动测试：`tests/vocabulary.test.mjs`。
- 规则说明：本节 `README.md`。
- 新增、删除或调整词表、停用词、频次阈值、候选长度、搭配范围、例句数量或权重公式时，必须同步上述四处并运行 `npm test`，避免源码、便携包、测试和文档产生版本差异。

## 4. 目录结构

### 4.1 前端

- `dist/index.html`
  - 前端单入口页面
- `dist/app.js`
  - 路由、Launcher、速算训练、PDF 阅读、言语词语积累的 UI 和交互，以及原生菜单业务动作的前端处理逻辑
- `dist/styles.css`
  - 共享样式
- `dist/mental-math-engine.js`
  - 前端运行时使用的速算引擎
- `dist/vocabulary-engine.js`
  - 打包运行时使用的离线词语提取、去噪和跨来源聚合规则
- `dist/vocabulary-worker.js`
  - 词语提取后台任务入口，向首页回传阶段、百分比、完成结果或错误

### 4.2 源逻辑与测试

- `src/mental-math-engine.js`
  - 速算引擎源码
- `tests/mental-math.test.mjs`
  - 速算引擎测试

### 6.2 常用命令

安装依赖后，可用以下命令：

```powershell
npm test
```

```powershell
npm run build:node22
```

或者使用工程内的打包脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-node22.ps1
```

### 6.3 `build-node22.ps1` 的作用

该脚本会：

- 切换到项目根目录
- 设置 `NPM_CONFIG_CACHE`
- 设置 `RUSTUP_HOME`
- 设置 `CARGO_HOME`
- 设置 `CARGO_TARGET_DIR`
- 调用 Node 22 执行 `tauri build --no-bundle`
- 将 release 目录中的 `moyu.exe` 复制为最终独立便携 EXE
- 不执行 NSIS、MSI 等安装包 bundler

当前脚本里使用的构建输出根目录是：

```text
D:\project\moyu_tauri\.cargo-target
```

## 7. 输出路径

### 7.1 主可执行文件

```text
D:\project\moyu_tauri\.cargo-target\release\moyu.exe
```

### 7.2 唯一权威便携版输出

本工程唯一权威最终产物是可直接运行的独立便携 EXE：

```text
D:\project\moyu_tauri\.cargo-target\release\bundle\portable\moyu_1.0.0_x64-portable.exe
```

约定如下：

- 以后默认以该独立 EXE 作为唯一最终交付物，不把 ZIP、NSIS 或 MSI 作为最终产物。
- 便携 EXE 无需解压、安装或卸载，直接运行。
- 不在项目根目录额外复制便携包。
- 每次代码或文档变更后，都必须重新生成该便携 EXE 并核对更新时间与哈希。

## 8. 运行与分发注意事项

- 本项目没有把 WebView2 打进便携包。
- 目标机器必须已安装 Microsoft Edge WebView2 Runtime。
- 直接运行 `moyu_1.0.0_x64-portable.exe`，不需要解压、安装或卸载。
- 应用设置、PDF 阅读进度、速算历史和词语积累数据仍保存在 Windows 应用数据目录，不写入便携包目录。
- Tauri 默认 bundler 已关闭，官方构建脚本固定使用 `--no-bundle`，随后由 PowerShell 生成独立便携 EXE。

## 9. 测试

当前已有测试：

- `tests/mental-math.test.mjs`
- `tests/vocabulary.test.mjs`
- `tests/pdf-reader.test.mjs`

覆盖点包括：

- 判题
- 薄弱项统计
- 评分阈值缩放
- `2*2估算` 题型和 `5%` 容错
- 言语考试词表命中与词类分类
- 非词表候选去噪和停用词排除
- 常见搭配与例句提取
- 后台提取进度达到 100%、Worker/取消控件存在、提取完成后不自动打开二级页
- 多 TXT 来源累计、同路径覆盖和权重重算
- 词语表每页最多渲染 100 项，筛选、排序和翻页不会一次生成全部行
- 首页、速算、PDF 与词语页都直接让 `#app` 占满系统窗口内容区，不再额外切分本地标题栏行

- 全局夜间主题和 PDF 独立夜间开关均能让 PDF 进入黑底白字状态，且不会改写隐藏图片设置
